# PostgreSQL Database Design Specification

## 1. Schema Design Philosophy

The database layer for `smart_water_management` is engineered directly in PostgreSQL 18 with Flyway schema migration scripts (`V1` through `V5`). 
It strictly follows third normal form (3NF) principles while maintaining high-performance analytical capabilities through specialized database views, window functions, and composite B-Tree indexes.

---

## 2. Table Specifications & Constraints

### 2.1 `regions`
- **Purpose**: High-level administrative prefecture or metropolitan water district.
- **Primary Key**: `id BIGINT GENERATED ALWAYS AS IDENTITY`
- **Natural Key**: `code VARCHAR(20) UNIQUE NOT NULL`
- **Audit Columns**: `created_at TIMESTAMPTZ`, `updated_at TIMESTAMPTZ`

### 2.2 `locations`
- **Purpose**: Physical geographic coordinates, ward, and installation structure for water meters and monitoring nodes.
- **Foreign Key**: `region_id BIGINT REFERENCES regions(id) ON DELETE RESTRICT`
- **Constraints**: `latitude` between -90.0 and 90.0, `longitude` between -180.0 and 180.0.

### 2.3 `customers`
- **Purpose**: Utility account holders across Tokyo-Kanto metropolitan areas.
- **Natural Key**: `customer_number VARCHAR(30) UNIQUE NOT NULL`
- **Domain Constraints**: `chk_customer_type` (`RESIDENTIAL`, `COMMERCIAL`, `INDUSTRIAL`, `MUNICIPAL`), `chk_customer_status` (`ACTIVE`, `INACTIVE`, `SUSPENDED`, `TERMINATED`).

### 2.4 `water_meters`
- **Purpose**: Physical smart meters and acoustic ultrasonic flow devices deployed in the field.
- **Natural Key**: `serial_number VARCHAR(50) UNIQUE NOT NULL`
- **Foreign Keys**:
  - `location_id BIGINT REFERENCES locations(id) ON DELETE RESTRICT`
  - `customer_id BIGINT REFERENCES customers(id) ON DELETE SET NULL`
- **Domain Constraints**: `chk_meters_status` (`ACTIVE`, `INACTIVE`, `FAULTY`, `MAINTENANCE`, `RETIRED`, `REMOVED`), `diameter_mm > 0`.

### 2.5 `meter_readings`
- **Purpose**: High-frequency telemetry stream capturing cumulative water consumption, pressure, and flow rates.
- **Composite Unique Constraint**: `CONSTRAINT uq_meter_reading_timestamp UNIQUE (meter_id, reading_timestamp)` — Prevents duplicate ingestion for identical telemetry intervals.
- **Domain Constraints**: `cumulative_reading_m3 >= 0`, `incremental_consumption_m3 >= 0`.

### 2.6 `water_bills`
- **Purpose**: Invoiced utility fees for billing cycles.
- **Natural Key**: `bill_number VARCHAR(50) UNIQUE NOT NULL`
- **Domain Constraints**: `chk_bills_status` (`ISSUED`, `PARTIALLY_PAID`, `PAID`, `UNPAID`, `OVERDUE`, `CANCELLED`), `total_amount >= 0`, `paid_amount >= 0`.

### 2.7 `payments`
- **Purpose**: Settlement records linked to invoices.
- **Natural Key**: `payment_reference VARCHAR(50) UNIQUE NOT NULL`
- **Foreign Key**: `bill_id BIGINT REFERENCES water_bills(id) ON DELETE RESTRICT`
- **Domain Constraints**: `amount > 0`.

### 2.8 `leak_alerts`
- **Purpose**: Algorithmic leak notifications generated by the heuristic telemetry detection engine.
- **Severity**: `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`.
- **Status Lifecycle**: `NEW` $\rightarrow$ `ACKNOWLEDGED` $\rightarrow$ `INVESTIGATING` $\rightarrow$ `WORK_ORDER_DISPATCHED` $\rightarrow$ `RESOLVED` / `FALSE_POSITIVE`.

### 2.9 `water_quality_records`
- **Purpose**: Laboratory physical-chemical assay measurements.
- **Parameters**: `ph_level` (6.5 - 8.5 target), `turbidity_ntu` ($\le$ 2.0 target), `residual_chlorine_mg_l` (0.1 - 1.0 target), `conductivity_us_cm`, `water_temperature_celsius`.
- **Potability**: `chk_potability_status` (`POTABLE`, `POTABLE_MONITORING_REQUIRED`, `NON_POTABLE`).

### 2.10 `maintenance_requests`
- **Purpose**: Field technician work orders and corrective repair tracking.
- **Status Lifecycle**: `PENDING` $\rightarrow$ `ASSIGNED` $\rightarrow$ `IN_PROGRESS` $\rightarrow$ `COMPLETED` $\rightarrow$ `CANCELLED`.
- **Foreign Keys**: `meter_id`, `alert_id`, `location_id`.

### 2.11 `app_users`
- **Purpose**: User accounts, credentials, and RBAC authorization.
- **Credentials**: Passwords securely hashed with BCrypt ($2a$ format). Plaintext passwords strictly forbidden.
- **Role Constraints**: `chk_users_role` (`ADMIN`, `OPERATOR`, `TECHNICIAN`, `ANALYST`, `AUDITOR`).

## 3. Database Views

### 3.1 `v_latest_meter_readings`
Resolves the most recent telemetry entry for each meter using `DISTINCT ON`:
```sql
CREATE OR REPLACE VIEW v_latest_meter_readings AS
SELECT DISTINCT ON (m.id)
    m.id AS meter_id,
    m.serial_number,
    m.status AS meter_status,
    m.customer_id,
    c.full_name AS customer_name,
    m.location_id,
    r.id AS latest_reading_id,
    r.reading_timestamp,
    r.cumulative_reading_m3,
    r.incremental_consumption_m3,
    r.water_pressure_bar
FROM water_meters m
LEFT JOIN customers c ON m.customer_id = c.id
LEFT JOIN meter_readings r ON m.id = r.meter_id
ORDER BY m.id, r.reading_timestamp DESC NULLS LAST;
```

### 3.2 `v_monthly_consumption`
Aggregates billed water volume by calendar month:
```sql
CREATE OR REPLACE VIEW v_monthly_consumption AS
SELECT 
    TO_CHAR(r.reading_timestamp, 'YYYY-MM') AS year_month,
    m.id AS meter_id,
    m.serial_number,
    c.id AS customer_id,
    c.full_name AS customer_name,
    reg.name AS region_name,
    COUNT(r.id) AS reading_count,
    COALESCE(SUM(r.incremental_consumption_m3), 0) AS total_consumption_m3,
    AVG(r.water_pressure_bar) AS avg_pressure_bar
FROM water_meters m
JOIN locations loc ON m.location_id = loc.id
JOIN regions reg ON loc.region_id = reg.id
LEFT JOIN customers c ON m.customer_id = c.id
LEFT JOIN meter_readings r ON m.id = r.meter_id
GROUP BY TO_CHAR(r.reading_timestamp, 'YYYY-MM'), m.id, m.serial_number, c.id, c.full_name, reg.name;
```

### 3.3 `v_outstanding_bills`
Monitors delinquent and pending receivables:
```sql
CREATE OR REPLACE VIEW v_outstanding_bills AS
SELECT 
    b.id AS bill_id,
    b.bill_number,
    b.customer_id,
    c.customer_number,
    c.full_name AS customer_name,
    b.total_amount,
    b.paid_amount,
    (b.total_amount - b.paid_amount) AS outstanding_amount,
    b.due_date,
    b.status,
    CURRENT_DATE - b.due_date AS days_overdue
FROM water_bills b
JOIN customers c ON b.customer_id = c.id
WHERE b.status IN ('ISSUED', 'PARTIALLY_PAID', 'OVERDUE')
  AND (b.total_amount - b.paid_amount) > 0;
```
